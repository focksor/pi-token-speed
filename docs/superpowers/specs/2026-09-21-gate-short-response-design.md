# 闸门短响应缺口修复：自适应分段数 + 保守窗口延长

**日期**：2026-09-21
**状态**：已批准（用户于对话中确认按候选 C 实施）
**目标文件**：`token-speed.ts`、`test-estimator.ts`、`README.md`
**前序**：`docs/superpowers/specs/2026-09-20-token-speed-glitch-design.md`（到达周期 + 历史闸门）

## 背景

用户报告"之前的毛刺去除算法都没有起作用"，并提议改用滑动多点采样平均。用虚拟时钟驱动真实扩展代码实测（见下）后确认：

1. **滑动平均不是修法，而是回归**。毛刺成因是单个离群到达（肥 chunk，Δtokens 可达正常值的 100 倍）。中位数是抗离群估计量，均值不是：`[100,100,100,100,100,100,100,5100]` 的中位数是 100，均值是 737，与当前算法的 5100 相比只是把污染摊薄到更长时间。实测"单肥块""相邻两肥块"这类当前算法**已经修好**的场景，滑动平均（N=8）会把 100 打回 3433–5100。

   | 场景（真实速率） | 当前算法 | 滑动平均 N=8 | 滑动窗 Σtok/Σtime N=8 |
   |---|---|---|---|
   | 冷启动 单个 500tok 肥块（100） | **100** ✓ | 3433 ✗ | 3433 ✗ |
   | 单肥块 N=2 邻接（100） | **100** ✓ | 5100 ✗ | 5100 ✗ |
   | 真实高速 2000 | 2000 ✓ | 2000 ✓ | 2000 ✓ |
   | 诚实抖动 50/200（125） | 125 ✓ | 125 ✓ | 125 ✓ |

   独立的网络研究结论一致：OpenAI 从不保证一个 SSE 事件一个 token（chunk 大小由服务端/proxy 控制）；网关合并 SSE 是有据可查的普遍现象（LiteLLM 曾因 nginx 缓冲整体攒批而加 `X-Accel-Buffering: no`）；业界标准修法是**按 usage 分摊逐 token 归属**（vLLM PR #42661 即为"server batches multiple tokens per SSE chunk"修 ITL），而非滤波。

2. **但存在一个真实的算法缺口**，它解释了用户"算法没生效"的观感（叠加一个运维因素，见"非算法因素"）：

   `HISTORY_MIN_CYCLES = HISTORY_SEGMENTS * 2 = 8` 是**周期数**门槛。一个响应必须有 ≥8 个周期才写入历史环。于是**交付粒度粗的 provider（每个响应只有少数 chunk）永远凑不满 8 个周期 → 历史永不写入 → 闸门永不启用**，冷启动缺口永不关闭。实测：

   ```
   短chunk provider（每响应 6 周期）：训练 12 个响应后遇污染 → peak=10100（真实100）✗ 闸门从未启用
   多chunk provider（每响应 24 周期）：训练  6 个响应后遇污染 → peak=100    ✓
   ```

   用户的真实数据支持该场景：`tiersync` 会话中 24452 个 assistant 响应里 **39.3% 的 output ≤200 tokens**、**66.1% 含 thinking**、**93.2% 含 toolCall**——短响应与工具调用占比很高。

## 根因

### 根因 A：闸门训练门槛按"周期数"设定，未考虑 provider 交付粒度

`HISTORY_MIN_CYCLES = 8` 的原意是"响应太短不足为证"。但这个门槛把**交付粒度**误当成**响应长度**：一个 2000 token 的回答若以 700ms/块 交付，只有 3 个周期；而一个 400 token 的回答若以 20ms/块 交付，有 20 个周期。前者信息量不小却被丢弃，后者信息量有限却被采信。

同时 `HISTORY_SEGMENTS = 4` 是固定值：`rates.length = 4` 时若允许写入，会按 `size = 1` 切成 4 段、每段 1 个样本——单点即"中位数"，分段中位数的抗噪作用完全失效。

### 根因 B：小窗口的 `min` 规则覆盖面不足

`SPEED_SMALL_WINDOW = 5` 时，5–7 周期的窗口已用中位数。但 8 周期窗口下 3 个污染周期（37.5%）即可在早期位置带跑中位数（实测 10100）。`min` 规则是唯一在"污染占多数"时仍然诚实的读数，而 `min` 的作用范围只有 2–4 周期。

## 目标

- 让**粗粒度交付的 provider** 也能训练历史闸门（不再因"每响应周期数 < 8"而永久静默）。
- 缩小"冷启动 + 早期少数污染"的残留缺口。
- 不引入任何写死的速度阈值，不改变闸门公式本身，不增加磁盘 IO。

## 非目标

- **不**采用滑动平均（理由见背景第 1 点，已实测否决）。
- **不**解决"冷启动 + 污染占多数（≥4/8）"：无历史时该场景在结构上与"诚实批量交付"不可区分（前序 spec §2 已论证），仍需历史先验。
- **不**改变 subagent 聚合、TTFT 计时、`lastShownSpeed` 速度不回退、`/reload` store 迁移。

## 设计

### 改动 1：自适应分段数 + 降低训练门槛

```
HISTORY_MIN_CYCLES: 8 → 4
segmentCount = clamp(floor(rates.length / 2), 2, HISTORY_SEGMENTS)
```

- `floor(rates.length / 2)` 保证每段至少 2 个周期，分段中位数才有意义（根因 A 的直接修正）。
- `min(..., 4)` 保持 `HISTORY_SEGMENTS = 4` 为上限，长响应的写入形状不变。
- 写入样本数随响应长度在 2–4 之间：4 周期 → 2 样本，8+ 周期 → 4 样本（与既有行为一致）。
- 代价：闸门启用所需响应数因 provider 而异（`HISTORY_MIN_SAMPLES = 12` 固定）。实测：

  | 每响应周期数 | 分段数 | 闸门启用所需训练响应数 |
  |---|---|---|
  | 4 | 2 | 6 |
  | 5 | 2 | 6 |
  | 6 | 3 | 4 |
  | 8 | 4 | 3 |
  | 24 | 4 | 3 |

  改动前，4–7 周期的 provider **永远不会**启用闸门（列末项不可达）。

### 改动 2：`min` 规则延长到 7 周期

```
SPEED_SMALL_WINDOW: 5 → 7
```

窗口 <7（即 ≤6 个可信周期）取 `min`，≥7 取中位数。

这是**保守方向**的取舍：`min` 保证不产生读数高于真实值的毛刺，代价是读数偏低。实测影响仅限于"窗口尚小 + 存在慢周期"的场景，稳态不受影响。

### 已实测的行为变化

| 场景（真实速率） | 改动前 | 改动后 |
|---|---|---|
| 冷启动 早期 3/8 污染（100） | 5100 ✗ | **100** ✓ |
| 短chunk provider 6周期/响应（100） | 10100 ✗ | **100** ✓（4 个响应后启用） |
| 正常 无污染（100） | 100 ✓ | 100 ✓ |
| 真实高速 2000 | 2000 ✓ | 2000 ✓ |
| 粗粒度 300ms/1s/2s provider | 100 ✓ | 100 ✓ |
| 冷启动 4/8 多数污染（100） | 5100 ✗ | 5100 ✗（仍需历史，见非目标） |
| 冷启动 思考突发 6/8（100） | 6100 ✗ | 6100 ✗（同上） |

### 代价（写入 README）

- **短抖动窗口更保守**：12 周期两态抖动（50/200，真实 125）仍读 125；但 6–7 周期的同一抖动会读 50。改动前读 200。两者都不等于真值 125——改动后落在保守一侧，与"数据少时取 min"的既定设计一致。
- **真值跃升的适应期不变**：仍是最多约 5 个响应（实测 100 → 2000 在第 5 个响应恢复显示），与前序 spec 记载一致。
- 闸门启用所需响应数变为 3–6 个（依 provider 交付粒度；改动前对少 chunk 的 provider 是**永不启用**）。

## 测试计划（`test-estimator.ts` 新增）

每个新断言必须**因本次改动回退而失败**（判别性验证），不能像既有回归那样在两个变体上都通过：

1. **短响应 provider 闸门可训练**：同一键连续投喂 12 个"每响应 6 周期"的健康响应（100 tok/s），随后投喂"每响应 6 周期、3/6 污染"的响应，峰值须 ≤150（真实 100）。改动前实测 10100，改动后 100。
2. **冷启动早期污染**：24 周期、前段 3 个肥块，峰值须 ≤150（真实 100）。改动前 5100，改动后 100。
3. **污染短响应不得吹大闸门**：连续 8 个"末周期带肥块"的短响应训练后，诚实 100 的读数须仍在 [90,120]（护栏：验证自适应分段数没有让闸门被污染抬高）。

既有 14 项断言必须保持全绿，`test-global.ts`（33 项）与 `tsc --strict` 同理。
