# 突发穿透修复：逐周期时长加权的中位数

**日期**：2026-09-21
**状态**：已批准（用户于对话中确认）
**目标文件**：`token-speed.ts`、`test-estimator.ts`、`README.md`
**前序**：`2026-09-20-token-speed-glitch-design.md`、`2026-09-21-gate-short-response-design.md`、`2026-09-21-smoothing-window-design.md`

## 背景

用户报告"重启后仍有毛刺"。这次我改用**读取用户实时 footer**（`zellij action dump-screen`，直接读到状态行）验证，首次拿到了真实现场数据——此前几轮只靠虚拟时钟，预测与真实偏差近一倍。

### 真实现场（用户机器，75 秒 / 149 帧）

```
#43  ⚡ 81.7  tok/s · TTFT 19.8s…
#44  ⚡ 49764 tok/s · TTFT 20.0s     ★ 毛刺（稳态中位数 102 的 488 倍）
#45  ⚡ 121   tok/s · TTFT 20.0s
```

同一 subagent 段独立复现：

```
sub general-purpose · 407ms…
sub general-purpose · 31784 tok/s   ★
sub general-purpose · 30836 tok/s   ★
sub general-purpose · 237   tok/s
```

### 虚拟时钟精确复现

长 TTFT 后首 token 以背靠背 delta 到达：5 个 delta（各 50 tok、间隔 1ms）产生 4 个 50000 tok/s 的周期；到第 8 个周期时窗口恰为

```
[50000, 50000, 50000, 50000, 98, 100, 100, 100]
```

→ `(100 + 50000)/2 = 25050`，与真实 49764 同源。

## 根因

**窗口按周期数量计权，1ms 周期与 50ms 周期等价。** 突发能在时间上只占几毫秒、却在计数上占满半个窗口，于是：

- 污染占少数 → 中位数正确丢弃（安全）；
- 污染恰好占一半 → **偶数样本的中位数退化为中间两项的均值**，污染值直接进入结果（`(100+50000)/2`）；
- 污染占多数 → 中位数跟随（已知极限，靠历史闸门）。

两个次要事实：

1. **不只 1ms**。实测扫描（delta 数 × 间隔）：2ms→25000、3ms→16667、5ms→10000、10ms→5000、20ms→2500、50ms→1000。因此任何"绝对时长阈值"都只能盖住很小一段——这一版初稿曾用 `SPEED_MIN_CYCLE_MS = 2` 过滤，实测**完全治不了 2ms 以上**，已否决。
2. **`min` 规则（<7 周期）没覆盖**：此场景有 8 个周期，超出范围。
3. **闸门没拦**：用户刚重启，历史为空（需 3 个响应训练）。

## 设计

```
weightedMedian(cycles: {rate, span}[])  — 按 span 加权求中位数
```

- `cycleRates` 返回 `{rate, span}` 而非裸速率。
- 累加权重至超过总权重一半，返回跨越点的速率；恰好落在边界时取两侧速率的**中点**。
- **权重相等时严格退化为普通中位数**（含偶数取中间均值的语义）——已在测试中显式验证，保证既有行为不变。

### 为何不用其他方案

| 方案 | 实测结果 |
|---|---|
| 过滤 `span < 2ms` | 只修 1ms；2ms 仍读 12550、5ms 读 5050 → **否决** |
| 时间覆盖门槛（窗口覆盖 <1s 走 min） | 模型测试中反而使稳态跨度 38→59、末值偏差 −31.6% → **否决** |
| 时间加权 | 突发全谱系抑制，稳态跨度 34→35、偏离 22.8%→23.8% → **采用** |

### 实测效果

突发扫描（峰值，✅=≤150）：

| delta 数 | 1ms | 2ms | 3ms | 5ms | 10ms | 20ms | 50ms |
|---|---|---|---|---|---|---|---|
| 修复前 5 | ✅100 | ✗12550 | ✗8383 | ✗5050 | ✗2550 | ✗2500 | ✗1000 |
| 修复后 5 | ✅100 | ✅100 | ✅100 | ✅100 | ✅100 | ✅100 | ✗1000* |
| 修复前 8 | ✅100 | ✗25000 | ✗16667 | ✗10000 | ✗5000 | ✗2500 | ✗1000 |
| 修复后 8 | ✅100 | ✅100 | ✅100 | ✅100 | ✗5000* | ✗2500* | ✗1000* |

\* 剩余项由**突发自身的交付速率**决定，与 delta 个数无关（实测：6/8/10 个 delta 在 20ms 间隔下峰值均为 2500）——突发持续得够久时，它**就是**那段时间的真实速率，加权不应也不能再将其视为离群值：这是信息论下限（无法区分“代理快速度交付”与“模型真的很快”），靠历史闸门而非方差分析解决。

稳态代价：跨度 34→35，最大偏离 22.8%→23.8%，阶跃时延不变。

## 非目标

- **不改**"速度不回退"（v1.3.0 的明确设计）。实测发现主段 `lastShownSpeed` 在无新响应时冻结 44 帧（22 秒），初判为缺陷，核对 git 历史后确认是**文档化的既定行为**（`612bb26`），故不擅自反转。已向用户报告，若需改为时效化可另行决定。
- **不解决**"污染占多数"（≥5/8）：无历史时与"诚实批量交付"结构不可区分。
