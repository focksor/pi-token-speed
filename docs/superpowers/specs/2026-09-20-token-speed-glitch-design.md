# 流式速度毛刺修复：到达周期估计 + 历史导出的可行域闸门

**日期**：2026-09-20
**状态**：待评审
**目标文件**：`token-speed.ts`（单文件扩展）、新增 `test-estimator.ts`

## 背景

`token-speed.ts` 当前（commit `2b923c2`）用"弹性分桶中位数"估计流式速度：把连续流式区间合并成宽度随响应年龄收缩的墙钟桶（`clamp(elapsed/3, 60ms, 200ms)`），取最近 5 个桶速率的中位数，且仅当恰好 2 个桶时启用 2.5 倍护栏。

该设计已修掉首块批量的经典毛刺，但在真实流形上仍有可复现的"高于常理"读数。用虚拟时钟（patch `performance.now`）驱动真实模块实测：

| 场景 | 真实速率 | 当前峰值显示 |
|---|---|---|
| 工具参数 blob 分 3 个肥大 chunk 到达 | ~620 tok/s | **1918 tok/s** |
| 两个相邻肥大 chunk（500 tok） | 100 tok/s 持续 | **2600 tok/s** |
| 两个相邻肥大 chunk（200 tok） | 100 tok/s 持续 | **1100 tok/s** |
| 4 周期中末尾 2 个被污染 | 100 tok/s 持续 | **4900 tok/s** |
| 1 delta 超短回复（50 tok / 250ms） | 不可测 | **192 tok/s** 并定格 |

### 根因

1. **墙钟桶让不相关的事件共享一个测量单位**。桶是固定时间窗，一个窗口里可能混入停顿与多笔突发；"中位数丢弃离群值"只在被污染的桶**不占多数**时成立。窗口未攒满 5 个桶时，3 桶中 2 桶被污染即可带跑中位数（实测 `recent=100, 2600, 2600` → 显示 2600）。
2. **超短回复的兜底公式把 prefill 时间算进产物时间**（`usage.output / 总耗时`），对 1–2 个 delta 的响应给出物理上偏高的值，且该值定格在 footer 上。

## 目标

- 流式显示不再出现"高于常理"的速度读数。
- **判定口径不写死**：可行域由该 (provider, model) 的**历史分布**导出（中位数 + 稳健离散度）。
- 冷启动行为与现状一致（无依据时不下判断，不误伤真实高速模型）。
- 算法代价可忽略：热路径微秒级、内存 KB 级、零磁盘 IO。

## 非目标

- **不**解决信息论下限：provider 持续粗粒度交付（代理批量转发）时，单靠时间规则无法区分"模型快"与"传输批量化"。闸门会对**持续**偏离历史的交付在数个响应后静默，但不声称能还原真实速率。
- **不**改 subagent 聚合的标签/计数逻辑，也不改 TTFT 计时。
- **不**引入配置项或常量上限（阈值全部由历史导出；仅统计窗口大小、最少样本数等结构参数为常量）。
- **不**持久化历史（见"决策"）。

## 设计

### 1. 周期定义（替代墙钟桶）

**周期 = 相邻两个"带 token 的到达"之间的区间**，记录 `Δtokens` 与 `span = t_end − t_start`，速率 `= Δtokens / span × 1000`。

- "带 token 的到达"判定：首个采样 `tokens > 0`，其后 `tokens > 前一个采样的 tokens`。因此 role-only / `finish_reason` / usage-only / 心跳等零 token 事件**天然不构成周期**，无需特判。
- 每个响应维护一个**采样缓冲**（沿用现有 `SpeedSample[]` 形态），估计器只读尾部最近 **8 个周期速率**（`SPEED_WINDOW = 8`，需最近 9 个带 token 的到达）。
- **有界裁剪必须改为仅按数量**（`SPEED_MAX_SAMPLES = 512`），**删除现有的 `SPEED_WINDOW_MAX_MS` 时间裁剪**。实测该时间裁剪（1800ms）会把粗粒度 provider 的保留窗口压到 **3 个样本 = 2 个周期**（delta 间隔 ≥700ms 时恒定如此）：

  | delta 间隔 | 时间裁剪后保留的到达数 | 周期数 | 显示 |
  |---|---|---|---|
  | 100ms | 19 | 18 | 满窗口（8 周期 + 中位数） |
  | 200ms | 10 | 9 | 满窗口 |
  | 300ms | 7 | 6 | 窗口不足 8 周期，但仍 ≥ 5，用中位数（单慢周期被丢弃） |
  | ≥700ms | 3 | 2 | 恰在 `SPEED_MIN_CYCLES` 下限，**仍会报数** |

  > **更正（实施期实测发现）**：本节初稿曾断言该裁剪会让粗粒度 provider「显示不出任何数字」，并在计划中据此设计回归测试。实测**该断言不成立**——裁剪后仍保留 2 个周期，`SPEED_MIN_CYCLES = 2` 仍会报数（把 1800ms 裁剪重新引入后，全部相关断言依然通过）。裁剪的真实危害是**质量退化而非无读数**：窗口被压到下限后估计器退化为「取 min」，于是**单个被拉长的慢周期会主导显示值**。判别性实测：11 个周期中第 7 个放慢到 50 tok/s——无裁剪全程显示 100，重新引入裁剪后中间出现 50。回归测试已按此改写。

  仅按数量的 512 样本上限已经是有界的内存保护（最高 512 × 16B ≈ 8 KB/响应），且实测 `estimate()` 在 512 样本下仅 **2.4 µs/delta**（40 样本时 0.8 µs）。
- 相比墙钟桶：一个肥大 chunk 只污染**它所在的那一个周期**，不会把一个可能混着停顿与多笔到达的时间窗整体折算成一个速率。

### 2. 实时取值

窗口内周期速率集合记作 `R`（已通过闸门，见 §3）：

```
|R| < SPEED_MIN_INTERVALS (=2)      → 不报数（沿用现有"保留上次显示速度"逻辑）
2 ≤ |R| < SPEED_SMALL_WINDOW (=5)   → min(R)          ← 窗口尚小时唯一诚实的读数
|R| ≥ SPEED_SMALL_WINDOW (=5)       → median(R)
```

`2 ≤ |R| < 5` 取 min 而非中位数，是因为中位数在窗口小时同样会被带跑（实测 4 个周期中末尾 2 个污染 → 中位数 4900）。窗口达到 5 后，中位数已要求污染过半才能穿透，且不会像"较小半区"那样**误压**真实抖动的流。

> **设计取舍记录**：曾考虑"取较小半区的中位数"（对污染更鲁棒），实测会系统性低估诚实抖动的流——两态交替 50/200 tok/s 的真实速率是 125，该规则稳定显示 50。故采用上表规则：鲁棒性由 §3 的闸门提供，而非牺牲对真实抖动的跟随。

**冷启动的残留缺口（已知限制）**：闸门未启用时，若窗口内污染样本**占多数**（8 个周期中 ≥4 个），中位数仍会被带跑（实测 4/8 污染 → 显示 5100）。这是与诚实批量交付不可区分的极限：

```
污染  [100,100,100,100,10100,10100,10100,10100]  中位数 5100
诚实  [ 50, 200, 50,200,  50, 200,  50,  200]  中位数  125
```

两者在"无序窗口"上的结构相同，任何顺序统计量都无法区分，只能靠历史先验（§3）区分。该缺口**并非新引入**：既有实现在同样场景下同样显示 5100，且在更常见的**少数污染 + 早期窗口**场景下更差（既有实现早窗口显示 5100，新规则显示 100）。

### 3. 可行域闸门（由历史导出）

按 **(provider, model)** 键控的历史环形缓冲，仅存内存：

- **键**：`ctx.model.provider` + `ctx.model.id`（pi 扩展 API 实测可用）。
- **样本写入**：每个响应结束时（`message_end`），把该响应**保留下来的**全部周期速率**分成 4 段**，各取中位数写入环（`SEG = 4`）。分段中位数使单个 spike 拖不动历史，同时让缓冲以"每响应 4 样本"的速度填充。

  > 权衡：超长响应（>512 delta）的写入只基于保留的尾部，而非整段响应。这让历史偏向响应的后段，但保持写入成本有界（实测 4000 样本的 harvest 约 96 µs，每响应一次），且对"该模型通常多快"的估计影响有限。
- **容量**：`HIST_CAP = 32` 个样本/键，超过则环形覆盖（32 × 8 B = **256 B/键**）。
- **闸门**：

  ```
  gate = median(history) + K × max(1.4826 × MAD(history), 0.3 × median(history))
  ```

  `K = 6`；`MAD` 为绝对中位差，`1.4826` 是其到 σ 的一致性系数；`0.3 × median` 是**离散度下限**，防止异常紧的历史把闸门设得过窄。
- **未启用条件**：历史样本 < `MIN_HISTORY = 12`（≈3 个响应）→ 闸门**不启用**，即**不做任何额外剔除**；显示由 §2 的周期规则单独决定。**绝不因"没见过"而压掉读数**。
- **拒绝行为**：窗口内被闸门拒的周期速率不参与 §2 取值；若 `|R| < 2` → **静默**（保留上次显示速度，不显示任何标记）。
- **每响应写入**：闸门自身也用历史，故写入是自洽的；写入值取自该响应**全部**周期速率的分段中位数，而非经过闸门的子集 —— 否则闸门只会向下收紧、永远无法向上适应。

用 MAD 而非标准差：实测在 20% 样本为 20 倍 spike 时，闸门从 212 → 230 tok/s（几乎不动），而标准差方案会被显著抬高。

### 4. 超短回复的最终值

周期不足（`|R| < 2`）时无法从区间测速，沿用兜底公式 `usage.output / 总耗时`，但**夹紧到闸门上界**：

```
final = gate ? min(formula, gate.bound) : formula
```

- 闸门未启用（冷启动）→ 保持现状（不做夹紧）。
- 闸门启用 → 公式值落在历史可行域内则原样显示（如 192 ≤ 280 → 仍显示 192），超出则夹到上界。
- 语义：显示的是**本次测量值，但不超过该模型历史可行域**，而非替换为估计值。

> 注意：冷启动下**闸门**不生效，但 §1/§2 的周期规则仍然生效 —— 它本身就会修掉"早期窗口被少数肥 chunk 带跑"（实测 +500 ×2 早期污染：既有实现 5100，新规则 100）。"闸门不启用"仅指不做剔除与夹紧，不等于显示序列与既有实现完全相同。

### 5. 与既有逻辑的关系

- **速度不回退**（`lastShownSpeed`）、**TTFT 实时等待计时**、**subagent 聚合**、**label 规则**、**`/reload` 迁移防御**全部保持不变。
- 周期采样替换的是 `estimateStreamSpeed` 的内部实现；它在 `message_update` / `message_end` 的调用点、以及 `live.speed` / `reportSpeed` / `lastShownSpeed` 的流转不变。
- 闸门与历史挂在现有 `globalThis` 共享 store 上（沿用 `getStore()` 的字段级防御式迁移模式），使 subagent 实例上报的会话也能写入/读取历史；`/reload` 存活，进程退出即丢。

## 决策（已与用户确认）

| 议题 | 决策 |
|---|---|
| 历史存哪里 | **仅内存**（`globalThis`），零磁盘 IO；代价是每次重启需重新积累约 3 个响应才启用闸门 |
| 闸门拒绝时是否可见 | **静默**（保留上次显示速度，不加标记） |
| 超短回复 | **修**：公式值夹紧到闸门上界 |
| 阈值来源 | **历史导出**（中位数 + 稳健离散度），不写死常量 |
| 判定口径 | 结构判定（到达周期）+ 合理性闸门（历史可行域），二者叠加 |

## 代价（写入 README）

- 真实速率超过历史中位数约 2.8 倍时，会有最多约 **5 个响应**的"暂无新数字"期（继续显示上次速度），随后恢复。实测 100 → 2000 tok/s 在第 5 个响应恢复显示 2000。
- 持续粗粒度交付（代理批量转发）在闸门积累足够历史后被识别并静默 —— 这是"不再显示高于常理的读数"的必然代价。
- 冷启动（无历史）不做剔除与夹紧；周期规则本身仍然生效，且在"早期窗口 + 少数污染"场景下优于既有实现。
- **冷启动残留缺口**：无历史时，若窗口内污染占多数（≥4/8），仍会被带跑（与既有实现相同的极限，见 §2）；闸门在积累约 3 个响应后关闭该缺口。
- 删除时间裁剪后，超长响应的采样缓冲会保留最多 512 个样本（约 8 KB），而非随时间窗口滚动。

## 测试计划

新增 `test-estimator.ts`，用**虚拟时钟**（patch `performance.now`，已验证可与真实模块协同）驱动真实扩展代码，断言：

1. **相邻肥大 chunk**（+500 / +200 各 ×2，含早期位置）：峰值显示 ≤ 真实值 × 1.5。
2. **工具参数 blob**（3 个肥大 chunk）：峰值不高于文本阶段的真实速率 × 1.5。
3. **批量 flush**（`purge 5x` 于 2 个 delta）：同上。
4. **静默后 flush**（2s 停顿后 2 个 delta）：同上。
5. **不误伤真实高速**：冷启动下 genuine 2000 / 400 tok/s 原样显示；热身历史后不显示为 0 或异常低值。
6. **诚实抖动不低估**：两态 50/200 的显示落在 [100, 150]（真实 125）。
7. **冷启动不误伤**：历史 < 12 样本时，genuine 2000 / 400 tok/s 原样显示（不做剔除、不做夹紧），且不出现异常低值。
8. **冷启动相对既有实现的改进**：既有实现在"早期窗口被少数肥 chunk 污染"时显示 5100，新规则必须显示 100（回归测试，逐例断言）。
8. **闸门向上适应**：历史训练于 100 后切到真实 2000，≤ 6 个响应内恢复显示 >1500。
9. **超短回复夹紧**：1 delta / 50 tok / 250ms 在闸门启用下显示 ≤ 上界；冷启动下等于公式值。
10. **粗粒度 provider 可测**：delta 间隔 300ms / 1s / 2s 的流必须能算出并显示速率（验证时间裁剪已删除）。
11. **无磁盘写入**：测试中断言未创建任何历史文件（以 `~/.pi/agent` 下无新增文件为准）。

既有 `test-global.ts` 33 项检查、`node token-speed.ts` 加载冒烟、`tsc --strict` 必须全绿。
